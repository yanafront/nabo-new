# Аудит Nabo — 18 октября 2026

Проверено 13 публичных представлений https://www.nabo.by в Chrome: мобильный экран 390×844 и desktop 1440×1000. Главная, товары, рецепты, категория супов, сырники, магазины, доставка, корзина, сохранённое, вход, политика и 404. Сценарии с изменением данных проверялись локально на fixtures; на публичном сайте рецепты и аккаунты не изменялись.

## Найдено и исправлено

| Проблема | Подтверждение | Исправление |
| --- | --- | --- |
| Гость ошибочно считается вошедшим | В production `/api/auth/me` возвращает 200/null; затем на каждой полной загрузке следовал ненужный `/api/cart` → 401. Старые тесты моделировали только 401 от auth/me. | Синхронизация проверяет наличие ID пользователя, восстанавливает гостевую корзину и не обращается к аккаунтной. Добавлены unit-регрессия с 200/null и браузерный сценарий с реальным контрактом. |
| Сломанное фото в доставке | В `/delivery` недоступна картинка `happylates.com/.../kartofelnaya-zapekanka-2.jpg`. | Фиксированный фотоблок с нейтральной иконкой при ошибке/отсутствии изображения. Заголовок и ссылка блюда остаются доступны. Сам исходный URL в БД не менялся. |
| Сбой каталога выглядит пустым экраном | Код доставки игнорировал error от useAsyncData. | Понятная ошибка с повтором загрузки, отдельное пустое состояние, отсутствие бесполезной пагинации при ошибке. Проверено e2e: 503 → повтор → карточки. |
| Неверная подпись во время расчёта | В сырниках отображалось «Считаем стоимость… / Найдено 0 из 7». | Статистика найденных продуктов появляется после завершения расчёта. |
| Приватные HTML-страницы без явного запрета кэширования | У корзины/аккаунта была только SEO-директива noindex. | `Cache-Control: private, no-store` для приватных страниц и персонализированных HTML-маршрутов с сессионной cookie. Статические файлы сохраняют обычную политику кэша. |

## Зависимости

Совместимые обновления lockfile: devtools 3.4.3, source-map-js 1.2.2, shell-quote 1.12.0, serialize-javascript 7.1.2 и связанные служебные пакеты. Удалена ненужная цепочка simple-git. Версия Nuxt осталась 3.21.11, функциональность приложения не переводилась на Nuxt 4.

`npm audit --omit=dev`: до обновления 17 предупреждений (3 critical, 13 high, 1 low), после — 11 high и 0 critical. Оставшиеся предупреждения относятся к транзитивной цепочке инструментов Nuxt/Nitro (listhen/node-forge, globby/micromatch/braces). Ни один из оставшихся отмеченных пакетов не перечислен в manifest финального `.output/server/package.json`; это проверка состава артефакта, не доказательство отсутствия всех рисков.

Полный audit включает дополнительные предупреждения тестовых инструментов Vitest/Tinypool. Предлагаемые npm исправления требуют major-переходов Nuxt 4 и Vitest 5. Это остаётся отдельной задачей миграции с проверкой конфигурации и CI; `audit fix --force` не использовался.

Исходные advisory: https://github.com/advisories/GHSA-v5rq-49vh-5v5c, https://github.com/advisories/GHSA-pqg4-j6r4-53mv, https://github.com/advisories/GHSA-68fv-2mgg-jv7q.

## Что прошло проверку

- На проверенных публичных страницах нет горизонтального переполнения, необработанных ошибок JavaScript и нарушений текущей CSP.
- Основной домен, canonical, robots, sitemap, схемы и preview noindex проверены в предыдущем доменном исправлении и повторно покрыты SEO smoke.
- Защита auth/cart endpoints, HttpOnly-сессия, SameSite, проверка Origin и allowlist image proxy сохранены.
- Unit-тесты, typecheck, production build, SEO smoke и браузерные сценарии для desktop/mobile.

## Ограничения и дальнейшие задачи

- В актуальном sitemap публичный backend отдаёт рецепты и статические страницы; индекс товаров пока пустой. Для появления product sitemap нужно проверить наполнение backend SEO feed и настройку `NUXT_SEO_INGEST_KEY`. Искусственные карточки/URL не добавлялись.
- Не измерялись реальные полевые Core Web Vitals; браузерные проверки не являются оценкой Lighthouse.
- Реальное определение местоположения зависит от разрешений и устройства; оно не подменялось тестовыми координатами на публичном сайте.
