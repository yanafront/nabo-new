# SEO / GEO / performance: повторный аудит

Дата: 13 октября 2026. Проверена существующая Nuxt 3 SSR-архитектура, а не выполнена повторная миграция. Дизайн и бизнес-сценарии сохранены.

## Было

Предыдущая SEO-работа уже обеспечивала серверный HTML рецептов, товаров и предложений Delivio, canonical, JSON-LD, robots и динамические sitemap. Повторно это не переписывалось.

Мобильный Lighthouse на production: Performance 71, Accessibility 96, Best Practices 96, SEO 100. LCP 5.4 с, CLS 0.115, TBT 60 мс. Наибольшие избыточные загрузки: PNG логотипа Nabo (441257 байт) и Санты (164515 байт). Логотипы загружались в исходном размере, CSS карты включался на всех маршрутах; первая строка каталога рецептов использовала lazy-loading. Найдены неверный aria-label ссылки входа и aria-label без роли у контейнера уведомлений.

## Сделано

- Уменьшенные локальные WebP для логотипов без изменения их пропорций/цветов; исходники оставлены. Nabo теперь около 12 КБ, Санта около 8 КБ.
- Responsive hero: 400/700/1000 px, srcset/sizes и соответствующий preload только на главной.
- Один preload реально используемого локального variable Inter; font-display: swap сохранён.
- Явная пропорция wordmark предотвращает сдвиг до декодирования. Фото рецептов/товаров имеют размеры; главные фото eager/high, нижние фото lazy. Первая строка рецептов и доставки eager.
- Leaflet CSS перенесён в компонент карты. Leaflet JS уже загружался динамически и не переписывался.
- Устранён повторный запрос предложений Delivio при гидратации, если SSR уже получил данные для того же адреса. Новый адрес и ручное обновление продолжают запрашивать актуальные данные.
- Гостевая проверка аккаунта без сессионной cookie возвращает null, не обращается к auth-бэкенду и не порождает ожидаемый 401 в консоли. Невалидная существующая сессия по-прежнему проверяется бэкендом.
- Исправлены два обнаруженных нарушения доступности.
- Пустая страница пагинации доставки возвращает 404.

## SEO / GEO

WebPage связан стабильными @id с WebSite и содержит фактические название, описание, язык и изображение. Recipe, Product/Offer, MenuItem/Offer, ItemList и BreadcrumbList сохранены. Источники и ингредиенты/шаги рецепта присутствуют в серверном HTML; искусственные рейтинги, авторы, даты обновления и цены не добавляются. Organization не выдумывается до определения оператора; FAQPage/Article не соответствуют текущим страницам.

llms.txt рассмотрен, но не добавлен: он не заменяет индексируемый HTML и не является подтверждённым механизмом ранжирования. Приоритет — доступный контент, стабильные сущности и реальные ссылки. Не используются скрытый текст и специальные инструкции AI-роботам. robots не блокирует полезный публичный контент.

HTTPS и перенаправление дополнительных доменов следует настроить в Vercel Domains: canonical уже указывает NUXT_PUBLIC_SITE_URL. Автоматический редирект всех Host запрещён, поскольку сломал бы preview и localhost. Preview noindex сохранён. Кэш публичных данных ограничен минутой; приватные auth/cart данные не помещаются в общий CDN-кэш. Общий HTML не кешируется публично, поскольку содержит состояние пользователя.

## Измерения и пределы

Сырые отчёты в `docs/audits/`. Production «до» и локальный «после» — разные условия, их нельзя выдавать за достоверное сравнение скорости. Локальный контроль: Performance 72, Accessibility 100, Best Practices 96, SEO 100; CLS 0, TBT 30 мс. Значения LCP/FCP подвержены задержке серверного API и конкуренции тестов; 90+ Performance не заявляется как достигнутое. Нужен повторный замер production после деплоя и полевые данные.

Не проведена слепая замена всей CSS/иконок: основной JS содержит Nuxt/Vue, карта уже отдельным chunk. Удаление глобальных стилей без анализа всех состояний ухудшило бы UX. Внешние фото рецептов всё ещё отдаются источником в большом размере; следующий шаг — image CDN с разрешёнными доменами, responsive variants и лимитами, либо собственное хранилище. Не скачиваем и не копируем весь чужой фотоархив. Отзывы/актуальные цены не подменяются статическими данными ради показателей.

## Проверка

- `npm run typecheck`, `npm run build`, `npm test`, `npm run test:seo`, `npm run test:e2e`.
- Lighthouse mobile: главная, `/recipes`, конкретный опубликованный рецепт, `/products`, известный товар и `/delivery`; минимум три запуска без параллельного тестирования. При сохранении результата проверять HTTP status и настоящий контент, а не страницу ошибки.
- PageSpeed Insights: повторить production-URL после деплоя. Полевые CWV появляются при достаточном объёме данных, обычно за окно 28 дней.
- Google Search Console: подтвердить домен, отправить `/sitemap.xml`, проверить live URL и HTML, отчёты индексации/CWV.
- Яндекс Вебмастер: sitemap, диагностика, проверка страницы/robots и исключённых URL.
- Google Rich Results Test и Schema.org Validator: рецепт и товар с реальными данными. Bing Webmaster Tools: обход и доступные отчёты AI-цитирования. Индексация/цитирование не гарантируются.

Официальные ориентиры: https://web.dev/articles/optimize-lcp , https://web.dev/articles/fetch-priority , https://developers.google.com/search/docs/appearance/structured-data/recipe , https://www.bing.com/webmasters/help/webmaster-guidelines-30fba23a .

Эти прогоны подтверждают отсутствие крупных сдвигов и наличие индексируемого HTML, но не достижение цели скорости. Запросы выполнялись с локального сервера к реальному Railway и внешним изображениям; первые проверки также совпадали с браузерными тестами. LCP рецепта 7.3 с, каталога продуктов 6.3 с, доставки 8.7 с требуют дальнейшей работы и повторной production-оценки. Карточка товара отдельно проверена автоматическим тестом исходного HTML и браузерными сценариями с изолированным ритейл API; валидный доступный production SKU для воспроизводимого Lighthouse не подставлялся фиктивно.

Финальные проверки: сборка и typecheck успешны, 240 unit-тестов, SEO HTTP smoke успешен. Из 70 браузерных сценариев 66 прошли сразу; четыре устаревших проверки ожидали PNG вместо WebP и старый aria-label. После корректировки ожиданий все затронутые тесты прошли (12 desktop/mobile проверок).
