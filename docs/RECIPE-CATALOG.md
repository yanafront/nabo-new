# Каталог рецептов Nabo

## Состояние миграции

Рабочие API и интерфейс используют `data/recipe-catalog.json` (version 2): 501 рецепт UniTools, 1138 нормализованных ингредиентов. Исходный `data/recipes.json` сохранён для воспроизводимой миграции и отката. Состав рецептов не генерируется и не заменяется автоматически.

В исходном датасете нет КБЖУ и шагов приготовления. Нельзя считать пункт приёмки «увидеть КБЖУ» выполненным до импорта проверенных данных. Подборки по калорийности и белку включают только рецепты с известной пищевой ценностью. Категории и показатель доступности определяются эвристически, это не гарантия наличия товара.

Edarix рассмотрен как будущий источник, но не подключён: документация API и учётные данные не предоставлены, при проверке https://edarix.ru/ получена ошибка сертификата TLS. Проверка сертификата не отключалась. Адаптер нужно реализовать после получения официального контракта и условий использования; его результат должен проходить `validateCatalog`. Ключ хранится только на сервере/в среде импорта. Браузер обращается исключительно к API Nabo.

## Импорт

Node >=22.12; команды из корня проекта:

```sh
npm run recipes:import -- legacy data/recipes.json
npm run recipes:import -- json /absolute/path/catalog.json
npm run recipes:import -- csv /absolute/path/recipes.csv data/recipe-catalog.json /absolute/path/ingredients.json
```

Импорт сначала проверяет весь файл, затем атомарно заменяет снимок. После изменения снимка необходимы сборка и деплой. Формат JSON: `{version:2, ingredients:Ingredient[], recipes:Recipe[]}`. Типы находятся в `shared/recipe/model.ts`. Для CSV названия колонок соответствуют полям Recipe, вложенные `ingredients`, `tags`, `nutrition`, `instructions` записываются JSON в CSV-ячейках; справочник ингредиентов передаётся отдельным JSON-массивом. Исходные лицензии, ссылки и авторство фото сохраняются.

Nutrition содержит calories/protein/fat/carbs, basis (`serving`, `recipe`, `100g`), calculationType (`source`, `calculated`) и source. Данные на 100 г переводятся на порцию только при известном yieldGrams. Изменение порций не меняет КБЖУ одной порции.

## Покупка

`/api/recipes` — поиск, категории, подборки и пагинация; `/api/recipes/:slug` — состав и справочник необходимых ингредиентов. Поиск использует нормализацию русского текста, распространённые окончания и явные синонимы; это не полноценный морфологический анализатор.

Экран рецепта масштабирует состав, исключает продукты «есть дома» и передаёт потребности существующему `/api/yandex/compare`. Сервер использует прежний backend для поиска SKU, а затем рассчитывает целые упаковки по указанному размеру. Сравнивается фактическая сумма покупки. Неизвестная масса, несовпадение г/мл и недостаточный остаток не трактуются как доступный товар. Для мер без надёжного перевода пользователь задаёт количество вручную.

Не найденные ингредиенты показываются отдельно. Неполный подбор не подтверждает соответствие бюджету. Ручное изменение количества или замена товара закрепляют количество упаковок вместо исходной потребности рецепта. Цена бюджета — стоимость покупок без доставки, а не цена фактически съеденной порции.

## Проверка

`npm test`, `npm run typecheck`, `npm run build`. Тесты покрывают миграцию, CSV, поиск/синонимы, базу КБЖУ, масштабирование, исключение pantry, округление упаковок, наличие и серверный контракт сравнения. Проверка реального ассортимента зависит от доступности upstream-магазинов.
