# Каталог рецептов Nabo

Единственный источник рецептов — сервис [nabo-recipes](https://github.com/yanafront/nabo-recipes) и PostgreSQL. На фронте нет локальной базы, импорта снимков или резервного каталога. Если API недоступен, показывается ошибка; пустой каталог остаётся пустым.

`NUXT_RECIPES_API_BASE` — серверная переменная с публичным HTTPS-адресом сервиса, без `/api` в конце. `/api/recipes` загружает опубликованные документы и применяет поиск, категории и пагинацию; `/api/recipes/:slug` открывает активный опубликованный рецепт. Неактивные рецепты не отображаются. Справочник ингредиентов изолируется по рецепту, чтобы одноимённые ID в разных документах не меняли поисковые запросы друг друга.

Админка `/admin/recipes` загружает рецепты и черновики из защищённого API. Новые блюда создаются в редакторе, сохранение черновика не меняет публичную версию, публикация обновляет каталог. Источники, атрибуция фото и КБЖУ приходят из бэкенда.

Фронт сохраняет масштабирование порций, выбор продуктов «есть дома», отдельный поиск ингредиентов и передачу searchQuery/exactName/exactUnit в retail API. Поиск товаров и корзины обслуживает основной бэкенд Nabo.

`tests/fixtures/recipes.json` содержит только три сокращённых примера для проверок и не импортируется приложением. Проверки: `npm test`, `npm run typecheck`, `npm run build`.
