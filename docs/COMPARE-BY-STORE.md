# Независимое сравнение магазинов

Фронт поддерживает шесть параллельных POST `/api/yandex/compare`, каждый с прежними `items`, `location` и новым `storeId` (`evroopt`, `green`, `gippo`, `sosedi`, `belmarket`, `santa`). Первый готовый магазин открывается автоматически; ручной выбор вкладки не сбрасывается последующими ответами. Результаты/ошибки остальных сетей обновляются независимо. Рекомендация во время загрузки явно относится только к проверенным магазинам. Сохранение корзины не меняется.

При редактировании во время загрузки устаревшие запросы отменяются; готовые строки и оптимистичный пересчёт остаются видны. Новые ответы не могут перезаписать изменённую корзину.

## Контракт retail-бэкенда

В `hellabanana/nabo_back` добавлен optional `CompareRequest.storeId`, проверка allowlist и ограничение поисков выбранной сетью. Без `storeId` поведение прежнее. Ответ остаётся `{ offers: [один магазин], ... }`. Логику подбора, избранное, количество и цены определяет прежний сервис бэкенда.

Фронт проверяет контракт через `/api/yandex/compare-capabilities` (серверный кэш 60 секунд). Пока поле не опубликовано или OpenAPI недоступен, сохраняется один прежний запрос. Это исключает шестикратную нагрузку на старую версию API, которая молча игнорирует незнакомые JSON-поля. После обновления бэкенда отдельные запросы включатся автоматически в течение минуты. Дополнительных переменных окружения не требуется.

## Проверки фронта

Typecheck, production build, 280 unit-тестов и 26 desktop/mobile браузерных проверок корзины прошли. Проверены первый ответ при ещё незавершённых пяти запросах, сохранение ручного выбора вкладки, изоляция ошибки магазина, отсутствие автоповторов, оптимистичное редактирование во время частичной загрузки и защита от устаревших ответов. Детектор возможностей учитывает nullable OpenAPI 3.1, используемый ASP.NET.
