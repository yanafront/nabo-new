# Nabo New

Nuxt 3 + Vue 3 + TypeScript. Интерфейс и сценарии основаны на `yanafront/nabo-front` (commit `e38fef7`): каталог шести магазинов, поиск продуктов, рецепты, корзина, сравнение и избранное. Поиск, сравнение и изображения обслуживает ASP.NET Core API на Railway. Добавлены регистрация, вход и выход.

## Запуск

Нужен Node.js 22.12+.

```sh
npm ci
cp .env.example .env
npm run dev
```

Открыть http://localhost:3000. По умолчанию используется `https://naboback-production.up.railway.app`. Для другого сервера задайте `NUXT_RETAIL_API_BASE` (без `/api` в конце); локальный бэкенд — `http://localhost:5031`.

```sh
npm run typecheck
npm test
npm run build
npm run preview
```

Production: `node .output/server/index.mjs`. Переменная `NUXT_RETAIL_API_BASE` задаётся в окружении сервера. Нужен Node-хостинг, статическая публикация не поддерживается. `PORT` и `HOST` настраивают HTTP-сервер. Внешний HTTPS завершается на reverse proxy.

## Интеграция

Браузер обращается к своему Nuxt-серверу; сервер пересылает запросы на Railway:

| Маршрут | Назначение |
| --- | --- |
| `POST /api/yandex/search` | Каталог магазина |
| `POST /api/yandex/compare` | Сравнение корзины |
| `GET /api/product-image?url=…` | Изображение товара |
| `POST /api/auth/register` | Регистрация по телефону и паролю |
| `POST /api/auth/login` | Вход и установка HttpOnly-cookie |
| `GET /api/auth/me` | Текущий пользователь |
| `POST /api/auth/logout` | Локальное завершение сессии |

Токен ASP.NET непрозрачный, не JWT. Nuxt хранит его в HttpOnly SameSite=Lax cookie, Secure при HTTPS, передаёт как Bearer и не возвращает access/refresh-токены JavaScript-клиенту. После истечения сессии нужно войти снова; backend пока не имеет refresh/logout endpoint. Выход удаляет cookie текущего браузера. Ответы auth не кешируются. Пользовательские cookies не передаются провайдерам или бэкенду. Ошибки и HTTP-статусы API сохраняются, демоданные при сбое не подставляются.

Соседи, Евроопт и Green используют каталоги сетей; Гиппо, Белмаркет и Санта — Яндекс Еду. Интеграции провайдеров находятся в бэкенде. Фронт сохраняет исходные форматы данных, цены BYN и выбор местоположения. Сравнение имеет ограниченное время ожидания: при большом списке или медленных магазинах его может потребоваться повторить.

`GET /api/recipes` остаётся локальным: на бэкенде нет маршрута рецептов. Набор из 501 рецепта и атрибуция CC BY-SA 4.0 сохранены в `data/RECIPES-LICENSE.md`. Корзины и избранное хранятся в localStorage этого браузера и не синхронизируются с аккаунтом. Оплата, стоимость доставки и автоматический перенос корзины магазину не подключены.

## Проверки

`npm test` проверяет корзины, рецепты, сравнение и HTTP-мост к тестовому бэкенду: тела запросов, статусы ошибок, изображения, cookie, Bearer и защиту auth от запросов с другого origin.

После `npm run build`, `npm run test:e2e` запускает сценарии интерфейса на desktop/mobile, используя установленный Google Chrome и production-сервер на порту 3100. Запросы магазинов подменяются для воспроизводимости. `npm run test:live` при запущенном сервере отдельно обращается к реальным магазинам и зависит от их доступности.

Git origin: `git@github.com:yanafront/nabo-new.git`.

## Результат проверки 26.09.2026

- Проверка TypeScript и production-сборка прошли.
- 53 unit/HTTP-теста прошли.
- Через production-сервер нового фронта поиск Green вернул 30 товаров; сравнение одного товара вернуло предложения всех шести магазинов без ошибок провайдеров.
- Главная и форма аккаунта проверены во встроенном браузере в узком окне.
- 18 Playwright-сценариев подготовлены, но автоматический запуск заблокирован средой: Chrome завершается с SIGABRT до выполнения сценариев. Полный браузерный прогон пока не подтверждён.
- Регистрация/вход проверены на тестовом HTTP-бэкенде; тестовые аккаунты в production не создавались.
