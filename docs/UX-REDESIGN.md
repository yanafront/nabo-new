# Nabo: продуктовый редизайн

## Основной сценарий

Написать список или блюдо → проверить корзину → выбрать магазин → скопировать список и перейти к покупке у магазина. Вход не является условием работы.

## Навигация

Три направления: Собрать, Корзина, Сохранённые. Магазины доступны с главной, профиль — иконкой в шапке. На корзине/сравнении показаны три шага процесса. История и другие разделы без данных не добавляются.

## Визуальная система

Белый фон `#FFFFFF` и тёплый терракотовый акцент `#B4432A` заменяют зелёную палитру по обратной связи пользователя. Цвет напоминает специи и керамику: связь с едой, без ярких промобаннеров доставки. Тёмный оттенок делает белый текст на кнопках контрастным; цвет используется дозированно в логотипе, основных действиях и активной навигации. Текст — нейтральный графит `#272727`, разделители — `#E6E6E6`, вспомогательные поверхности — почти белые. Брендовые переменные называются `--brand`, `--brand-hover`, `--brand-soft`, независимо от конкретного оттенка.

Рекомендацию определяют данные, а не яркость карточки. Зелёный применяется только как небольшой семантический сигнал наличия. Ошибки содержат явный текст; предупреждения — янтарные. Фирменные цвета магазинов ограничены их маленькими знаками.

Единый файл `assets/css/design-system.css` заменяет два противоречащих CSS-слоя. Системные шрифты не требуют внешнего сервиса. Размеры, интервалы, формы, списки и кнопки общие для всех экранов. Поддержаны focus-visible, reduced-motion и safe-area мобильных устройств.

## Правила доверия

- «Лучшая полная корзина» требует покрытия всех позиций, доступности и достаточного суммарного остатка, без ошибок источника.
- Экономия сравнивается с ближайшим по цене полным предложением с тем же набором позиций и количеством. Без второго полного предложения экономия не выводится.
- Разные подобранные бренды/упаковки раскрываются в пояснении. Это не доказательство одинакового SKU в каждом магазине.
- Цена неполной корзины подписана «за найденные товары» и не получает рекомендацию полной.
- Разделение на два магазина появляется только при полном покрытии и положительной экономии относительно лучшей полной корзины; если полной корзины нет, может появиться как способ собрать весь список. Доставка обоих магазинов неизвестна и не входит в сумму.
- «Без замен» фильтрует другое название и упаковку. «Обязательно» явно выделяет отсутствие товара. Изменение настроек сохраняется вместе с корзиной.
- Время получения и источник доступны по раскрытию, не занимая главный экран.

## Состояния

Первый запуск — поле и работающие примеры, без обязательного онбординга. Пустая корзина предлагает собрать список. Поиск и подбор показывают понятный статус и отмену. Сравнение использует skeleton, ошибки — повтор с сохранением корзины. Offline-баннер объясняет, что локальная корзина сохранена. Недостающие ингредиенты показываются до перехода к сравнению. Мобильный picker открывается снизу, замена в корзине раскрывается inline.

## Границы реального продукта

Нет обещаний LLM-понимания произвольных комбинированных запросов, недельного плана по бюджету, оплаты, автоматического переноса корзины, синхронизации списков между устройствами и гарантированной доставки. Продукт использует существующие работающие API. Готовность к сотням тысяч пользователей требует отдельной проверки нагрузки, лимитов провайдеров, хранения и надёжности backend; визуальный редизайн этого не подтверждает.
