# Товарный SEO-индекс

## Подключение

1. Создайте секрет: `openssl rand -hex 32`.
2. Railway → сервис **nabo-recipes** → Variables: `SEO_INGEST_KEY`.
3. Vercel → проект Nabo → Settings → Environment Variables → **Production**: `NUXT_SEO_INGEST_KEY` с точно тем же значением. Адрес этого сервиса в `NUXT_RECIPES_API_BASE`, например `https://nabo-recipes-production.up.railway.app`, без `/api`.
4. Перезапустите Railway и выполните redeploy Vercel. Ключи не должны иметь префикс PUBLIC и не публикуются в Git, браузере или сообщениях.
5. Войдите служебным аккаунтом, откройте `/admin/recipes` → **SEO товаров**, нажмите «Проверить».

Проверка доступна только редактору и не меняет товары: в backend отправляется пустой batch. Она показывает отсутствие ключа на фронте, отклонённый ключ, недоступный API или готовность. При отклонённом ключе проверьте обе переменные и их окружение; backend может отклонять и незаданный ключ. Значения секретов не возвращаются и не логируются.

## Первое наполнение

На `/admin/seo-products` выберите сеть и 1–5 запросов, например «Молоко», «Яйца куриные», «Сметана». Кнопка ищет до 20 реальных товаров по запросу через `/api/yandex/search/batch` и записывает только возвращённые ID, сеть, название, фасовку и фото. Товары другой сети и некорректные записи отбрасываются. Корзина не меняется. Количество обработанных записей включает обновлённые — это не число новых товаров.

Повторите для нужных магазинов и других запросов. Это управляемое начальное наполнение, а не полный обход каталогов сетей. Дальше товары попадают в индекс автоматически из обычного поиска, batch-поиска, загрузки карточки и resolve. На preview-доменах автоматическая запись отключена. Фоновые записи не задерживают пользовательский ответ; сбои логируются без персональных данных и секретов.

В PostgreSQL уже существует `nabo_recipes.seo_products`; миграция не нужна. Уникальность — `(store_id,id)`, поэтому повторная запись обновляет товар без дублей. Цены, телефон, состав корзины и координаты не сохраняются в SEO feed. Поиск использует выбранную точку, но в индекс она не передаётся.

## Проверка результата

- В админке — готовое подключение и ненулевой счётчик.
- `GET https://www.nabo.by/api/seo-products?page=1` — реальные записи.
- `https://www.nabo.by/sitemap.xml` — раздел `products-1.xml`, затем следующие части по 2000 товаров.
- `https://www.nabo.by/sitemaps/products-1.xml` — URL `https://www.nabo.by/product/{store}/{id}`.
- `/products` и `/stores/{store}` — ссылки на известные товары для обхода поисковиками.

Публичные feed и sitemap кешируются: появление после импорта может занять несколько минут. Backend включает в общий актуальный каталог товары, встречавшиеся в последние 30 дней. Карточки загружают актуальные сведения отдельно; SEO feed не является базой цен и не гарантирует наличие товара по любому адресу.

Фронтенд не может установить переменные в Vercel/Railway без доступа к этим сервисам. До назначения совпадающих ключей публичный индекс останется пустым, даже при корректном коде.
