# Каталог рецептов Nabo

## Состояние миграции

Рабочие API и интерфейс используют `data/recipe-catalog.json` (version 2): **41 рецепт, 41 набор КБЖУ на порцию, 38 фотографий**. Отобраны русскоязычные белорусские и европейские блюда: драники, колдуны, мачанка, холодник, борщ, сырники, пельмени, вареники, картофельная запеканка, супы, салаты и европейская выпечка. Всемирный каталог из 501 блюда больше не является каталогом по умолчанию. URL оставленных блюд сохранены. Для трёх белорусских блюд источник не предоставил фото — интерфейс показывает существующую заглушку, чужие блюда за их фото не выдаются.

Источник: [UniTools World Recipes 2.0.0](https://github.com/farcrak/unitools-recipes), снимок источника от 2026-09-02. [Полный готовый JSON](https://theunitools.com/data/unitools-recipes-v1.json). Отобранные исходные записи сохранены в `data/recipe-source-familiar.json`; старый `data/recipes.json` оставлен для истории. Лицензия данных CC BY-SA 4.0; автор и собственная лицензия каждой фотографии сохранены в imageAttribution. КБЖУ — расчёт источника, не лабораторное измерение. После изменения названий и разделения неколичественных ингредиентов исходный расчёт не пересчитывается. Шаги и состав не генерируются.

Это **обновление и отбор актуальной готовой базы UniTools**, а не новая сторонняя база. Проверен [Russian Recipes](https://github.com/chipslays/russian-recipes-parser): отдельные ингредиенты есть, но КБЖУ отсутствует, а проверенные ссылки st.vkuso.ru возвращают HTML FASTPANEL вместо изображений; в рабочие данные не импортирован. RuRecipes-93k ограничен некоммерческой лицензией, поэтому не используется. Полная готовая открытая русскоязычная база привычных белорусам блюд с действующими фото и КБЖУ пока не найдена.

«Сметана и варенье», «Сметана и зелень», «Соль и перец» разделяются **только при отсутствии общего количества**. Если дана общая масса смеси, импорт требует уточнения количества каждого продукта и не удваивает массу. Неоднозначные рецепты с такими количественными составами в подборку не включены. Запросы с `и`/`или` и разделителями `/`/`;` в справочнике отклоняются валидатором. Старое уведомление о ненайденных «Сметане и варенье» в localStorage преобразуется в две отдельные позиции; купленные товары сохраняются.

Подборки по калориям и белку используют реальные данные источника. Категории и показатель доступности определяются эвристически, это не гарантия наличия в магазинах. Подключение каталога не гарантирует подбор каждого SKU: ошибки/отсутствие ассортимента upstream по-прежнему показываются пользователю.

## Импорт

Node >=22.12; команды из корня проекта:

```sh
npm run recipes:import:familiar
# Произвольные файлы должны содержать отдельные ингредиенты:
npm run recipes:import -- json /absolute/path/catalog.json
npm run recipes:import -- csv /absolute/path/recipes.csv data/recipe-catalog.json /absolute/path/ingredients.json
```

Импорт сначала проверяет весь файл, затем атомарно заменяет снимок. После изменения снимка необходимы сборка и деплой. Формат JSON: `{version:2, ingredients:Ingredient[], recipes:Recipe[]}`. Типы находятся в `shared/recipe/model.ts`. Для CSV названия колонок соответствуют полям Recipe, вложенные `ingredients`, `tags`, `nutrition`, `instructions` записываются JSON в CSV-ячейках; справочник ингредиентов передаётся отдельным JSON-массивом. Исходные лицензии, ссылки и авторство фото сохраняются.

Nutrition содержит calories/protein/fat/carbs, basis (`serving`, `recipe`, `100g`), calculationType (`source`, `calculated`) и source. Данные на 100 г переводятся на порцию только при известном yieldGrams. Изменение порций не меняет КБЖУ одной порции.

## Покупка

`/api/recipes` — поиск, категории, подборки и пагинация; `/api/recipes/:slug` — состав и справочник необходимых ингредиентов. Поиск использует нормализацию русского текста, распространённые окончания и явные синонимы; это не полноценный морфологический анализатор.

Экран рецепта масштабирует состав, исключает продукты «есть дома» и передаёт потребности существующему `/api/yandex/compare`. Сервер использует прежний backend для поиска SKU, а затем рассчитывает целые упаковки по указанному размеру. Сравнивается фактическая сумма покупки. Неизвестная масса, несовпадение г/мл и недостаточный остаток не трактуются как доступный товар. Для мер без надёжного перевода используется одна упаковка с предложением проверить количество.

Не найденные ингредиенты показываются отдельно. Неполный подбор не подтверждает соответствие бюджету. Ручное изменение количества или замена товара закрепляют количество упаковок вместо исходной потребности рецепта. Цена бюджета — стоимость покупок без доставки, а не цена фактически съеденной порции.

## Проверка

`npm test`, `npm run typecheck`, `npm run build`. Тесты покрывают миграцию, CSV, поиск/синонимы, базу КБЖУ, масштабирование, исключение pantry, округление упаковок, наличие и серверный контракт сравнения. Проверка реального ассортимента зависит от доступности upstream-магазинов.
